# 非功能规格

基线日期：2026-11-01。以下区分现有机制和发布验收目标；验收结果应附实际环境与记录，不把目标值写成实测结论。

| 编号 | 质量属性 | 现有机制 | 发布验收目标与方法 |
| --- | --- | --- | --- |
| N01 | 数据完整性 | PDF、元数据与工作区文件作为事实来源；SQLite 可重建；原子写入、文件锁及版本检查控制并发修改。 | 在隔离测试数据上验证重启后笔记、批注、复习进度仍在；移除测试索引后可重建；过期版本写入被拒绝。 |
| N02 | 来源可追溯 | 来源记录含论文标识、页码、摘录及正文版本；图谱摘录在入库前与指定页核对。 | 用真实摘录和构造的不匹配摘录分别验收；不匹配项不入库；来源变更后能识别旧证据。 |
| N03 | 隐私与配置 | Web 端口绑定本机；Python RPC 在 Compose 内部通信；私有配置与运行数据独立保存。 | 默认仅开放 `127.0.0.1:3000`，不映射 17437；仓库及导出中无模型密钥；AI 调用使用用户自己的额度。 |
| N04 | 材料范围 | 模型收到本轮选择的来源；任务绑定来源范围与正文版本，工具只能读取所提供资料。 | 默认单篇与显式多篇分别验收，未选论文不能通过工具读入；资料范围变化后不能继承更广来源的旧会话。 |
| N05 | 故障恢复 | 任务持久化、事件记录、取消和中断状态；批注有重试与重复提交保护。 | 验证取消、断开连接、服务重启后的状态与历史；失败操作不重复写入，不清空已有工作区。 |
| N06 | 可安装性 | 根目录 Docker Compose 编排 Web 与 Python 服务，SQLite 无需单独安装数据库。 | 在干净目录按 README 配置和构建，访问 `/workspace`，走通无 AI 阅读流程；配置 API 后单独验收 AI 流程。 |
| N07 | 交互响应 | 任务状态可更新和取消；检索在本机执行，图谱按可见范围筛选。 | 以 50 篇文字 PDF、100 条笔记作为计划基准，记录首次索引时间及 20 次查询；目标查询 P95 ≤ 2 秒。该基准尚待执行。 |
| N08 | 可用性 | 中文阅读入口、来源回跳、保存状态、明确材料选择和逐题复习。 | 计划邀请 3–5 名目标读者完成统一任务，记录独立完成情况、求助点和误解；据此调整入口与提示。 |
| N09 | 可维护性 | TypeScript/Python 分工、结构校验、自动化测试与固定依赖文件。 | 文档链接可解析，核心回归通过；变更说明包含受影响流程和验证方式。第三方许可证随源码保留。 |
| N10 | 备份可恢复 | 成果 ZIP 与完整服务备份各有入口；完整快照统一保存 data、runtime。 | 在独立测试目录完成备份—恢复演练，核对 PDF、笔记、题组和任务；凭据重新配置后再验收模型连接。 |

## 运行与资源边界

- 主要运行环境为支持 Docker Compose 的个人电脑与现代桌面浏览器。Windows 直接运行源码涉及本机原生依赖，单独验证。
- AI 时延和费用受用户所选端点、模型和额度影响，单独记录；导入、全文索引、个人检索与人工编辑的验收不依赖模型。
- 完整离线生成、自动 OCR、多人访问和公网部署作为后续设计议题。首版按本机个人使用条件验收。
- 图谱关系表示资料中的主题或主张；摘录校验保证来源存在，关系含义仍由读者核对。
