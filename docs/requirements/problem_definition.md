# 问题定义与产品定位

整理日期：2026-11-01。本次工作从已有完整 Demo 出发，整理可公开获取、可本机运行的课程项目。

## 1. 需要解决的问题

教育研究阅读常涉及论文原文、批注、概念解释、研究笔记与复习材料。材料分散时，读者需要反复查找页码、搬运摘录，也容易把自己的理解或模型解释误记为作者结论。教研阅记将这些操作放在同一个阅读工作区，让研究成果持续保留来源。

以上是当前的问题假设。首轮计划邀请 3–5 名目标读者试用，观察他们能否完成“读原文—批注—解释—整理笔记—复习—回看证据”的流程；目前不将这项计划写成已有用户调研结果。

## 2. 5W1H

| 维度 | 本项目的回答 |
| --- | --- |
| Who：谁使用 | 阅读教育学论文的学生、教师与初步开展教育研究的读者；首版按个人本机使用设计。 |
| What：解决什么 | 保留阅读位置、原文批注和笔记来源，按明确选择的资料进行辅助理解、自测与概念整理。 |
| Why：为什么需要 | 降低摘录搬运和来源追溯成本，使读者能核对模型输出，并保留自己的判断。 |
| When：何时使用 | 文献精读、课程阅读、组会准备、研究问题梳理及阅读后的复习。 |
| Where：在哪里 | 在用户自己的电脑运行 Docker Compose，通过浏览器访问本机工作区。 |
| How：如何实现 | PDF 阅读与批注、文件持久化、SQLite 全文索引、PaperFlow 阅读任务、人工确认笔记与证据关系。 |

## 3. 产品描述模板

> 对于需要读懂、记住并追溯教育研究文献的学生与教师，教研阅记是一款本机论文阅读与学习 Web 应用。它将 PDF 批注、选文解释、研究笔记、自测和证据图谱连接为一个工作流，帮助读者在整理成果时保留原文来源。

| 模板要素 | 定义 |
| --- | --- |
| 谁 | 以教育研究阅读为主要任务的个人读者。 |
| 诉求 | 理解难懂段落、积累可核对的笔记、检查理解、再次找到证据。 |
| 产品类别 | 本机运行的论文阅读与学习工作区。 |
| 主要特性 | 阅读批注直接写入 PDF；解释和生成操作由读者发起；笔记可编辑和确认；关系携带页码、摘录与正文版本。 |
| 与 Zotero 的区别 | Zotero 的官方定位侧重研究来源的收集、组织、引用与分享；本项目将重点放在教育论文的理解、练习和证据整理流程。[Zotero 官方入门说明](https://www.zotero.org/support/quick_start_guide) |
| 与 NotebookLM 的区别 | NotebookLM 的官方说明覆盖基于来源的聊天与材料转换；本项目选择本机 PDF 持久化、自带 API 配置和逐条关系审核，围绕个人阅读成果组织功能。[官方产品说明](https://support.google.com/notebooklm/answer/16164461?hl=zh-Hans) |

## 4. 当前范围与后续方向

当前 Demo 已包含文献库、PDF 阅读批注、阅读助手、学习笔记、逐题复习、教育概念库、个人检索、证据图谱、研究待办及成果导出。功能要求见[功能规格](functional_spec.md)，验收流程见[用户故事](user_stories.md)。

首版输入以带文字层的 PDF 为主。扫描件可阅读和批注，自动 OCR、多格式上传、多人协作、自动跨论文综述与关闭页面后的系统推送留待后续评估。AI 功能使用用户自己的 OpenAI 兼容 API 和额度；导入、检索及人工整理无需模型调用。

原始 [MindBranch AI 构想](../mindbranch_ai_specification_document.md)提供了知识整理与主动学习方向；本次范围采用已有 Demo 的文件存储、SQLite 和本机服务实现，具体技术选择见[技术调研](../algorithm/research.md)。

## 5. 首轮试用要验证的假设

1. 读者能找到并完成一条完整阅读流程，而不需要持续口头指导。
2. 读者能区分论文原文、自己的笔记与模型补充说明，并成功回跳来源。
3. 逐题作答和自评有助于暴露理解中的疑问；是否改善学习效果仍需后续研究。
4. 用户能理解 API 配置、调用时机和本机保存位置，愿意继续使用或提出具体改进。

试用记录计划包含任务完成情况、操作障碍、来源核对情况和后续使用意愿，采用参与者编号记录，不预设满意度结果。
